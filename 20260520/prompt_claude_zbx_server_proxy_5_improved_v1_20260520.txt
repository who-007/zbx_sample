# 2. 受け入れ基準（Acceptance Criteria）
================================================================================
<acceptance_criteria>
以下を全て満たすことを完了条件とする。

  AC-1. Zabbix Server が起動し、Web UI に管理者でログインできること
        （初回ログイン確認手順・初期パスワード変更手順を含む）。
  AC-2. ホストA / ホストB の Agent2 がそれぞれ Zabbix に登録され、
        各ホストで監視アイテムが正常に収集されること。
        以下5項目以上が Latest data に表示されること。
        
        - agent.ping
        - system.cpu.load
        - vm.memory.size[available]
        - vfs.fs.size[/,free]
        - net.if.in[eth0]
        
  AC-3. scripts/dev_setup.sh（開発環境）および
        scripts/prod_setup.sh（実運用環境）を実行して、
        エラー無しで全コンテナが起動すること。
  AC-4. scripts/check_health.sh を実行して全ヘルスチェックがパスすること
        （HTTP 200・DB 接続・zabbix_get 応答・SNMP 疎通 等）。
  AC-5. 単体テスト・結合テスト・システムテストのチェックリストが全てパスし、
        レビュー記録に「指摘無し」が残ること。
</acceptance_criteria>

## 5-2. 開発環境 Docker ネットワーク

| ネットワーク名            | サブネット       | 接続コンテナ                                   |
|:--------------------------|:-----------------|:-------------------------------                |
| zbx_net_frontend          | 172.20.0.0/24    | nginx                                          |
| zbx_net_backend_host_a    | 172.20.1.0/24    | zabbix-server, mysql-a, nginx, agent2-a        |
| zbx_net_backend_host_b    | 172.20.2.0/24    | zabbix-proxy, mysql-b, agent2-b                |

- Zabbix Agent2 は「アクティブモード」で動作させる（Agent2 → Server/Proxy 方向の接続）。

【DooD 固有の注意事項 — 必ず設計書に記載すること】

  時刻ずれが発生した場合のトラブルシューティング手順を手順書に記載する。

# 8. スクリプト仕様（必須）

<script_specification>
## 8-1. スクリプト一覧

| スクリプト                         | 役割                                                       |
|:---------------------------------|:----------------------------------------------------------|
| scripts/provision_common.sh      | 共通ネットワーク・ボリューム作成、環境変数チェック、シークレット初期化 |
| scripts/dev_setup.sh             | 開発環境一括構築（provision_common.sh 呼び出し＋全コンテナ起動）|
| scripts/prod_setup.sh            | 実運用環境一括構築（ホスト単位での起動手順）                  |
| scripts/check_health.sh          | ヘルスチェック（HTTP・DB・zabbix_get・SNMP 疎通）自動化       |
| scripts/collect_diagnostics.sh   | 障害時ログ・設定収集（タイムスタンプ付き ZIP 出力）           |

## 8-2. スクリプト共通実装規約

全スクリプトは以下を必ず満たすこと。

```bash
#!/usr/bin/env bash
# スクリプト説明（日本語）
set -euo pipefail
# IFS の設定
IFS=$'\n\t'
```

- **冪等性**: 何度実行しても同じ結果になるよう実装する。
  （例: ネットワーク・ボリュームが既存の場合は skip する）
- **ログ出力**: 以下のログレベルを定義し、logs/ にタイムスタンプ付きで出力する。
  ```
  [INFO]  正常処理
  [WARN]  警告（処理は継続）
  [ERROR] エラー（処理中断）
  ```
- **終了コード**: 成功=0, 失敗=1 以上 を返す。
- **タイムアウト**: コンテナ起動待ちは最大 120 秒（5 秒間隔でリトライ）とする。
- **コメント**: 全て日本語で記載する。
- **色付き出力**: tput が利用可能な場合は INFO=緑, WARN=黄, ERROR=赤 で出力する。
</script_specification>

# 9. compose.yaml 実装規約
================================================================================
<compose_specification>
- Docker Compose V2 前提とする。
全 compose.yaml に以下を必ず実装すること。

- **healthcheck**: 全サービスに定義する。
  ```yaml
  healthcheck:
    test: ["CMD", "コマンド"]
    interval: 10s
    timeout: 5s
    retries: 5
    start_period: 30s
  ```
- **depends_on**: service_healthy 条件で依存関係を定義する。
- **restart**: unless-stopped を設定する。
- **logging**: json-file ドライバ（max-size: 10m, max-file: 3）を設定する。
- **環境変数**: 全て .env から参照し、compose.yaml にハードコードしない。
- **ボリューム**: DB データ・設定ファイル・ログは named volume または
  bind mount で永続化する。
- **ネットワーク**: 必要最小限のネットワークのみに接続する。

<db_initialization_rule>

Zabbix Server 起動前に
MySQL readiness を確認すること。

初回起動時は:
- schema import 完了
- users table 作成
- DB version 整合

をログ確認すること。

</db_initialization_rule>

<healthcheck_rule>

healthcheck は実サービス疎通を確認すること。

禁止:
- echo
- true
- sleep のみ

例:
- MySQL: mysqladmin ping
- nginx: curl -f
- zabbix-server: nc -z localhost 10051
- snmp: snmpwalk

</healthcheck_rule>
</compose_specification>

  - 改善点および提案の取り込み

# 13. セキュリティ対策（必須）
================================================================================
<security>
  - シークレットは .env で管理し、.env.example をテンプレートとして配布する。
    .env はリポジトリにコミットしない（.gitignore で除外）。
  - DB パスワードはハードコード禁止。初回起動時に自動生成して secrets/ に保存する。
  - Web UI はデフォルトでローカルネットワークのみバインドする（127.0.0.1 指定）。
    実運用では Nginx リバースプロキシ＋Basic 認証 または LDAP 認証を設定する。
  - SNMP コミュニティ名は "public" のまま実運用しない。.env で変更必須とし、
    手順書に変更手順を明記する。
  - コンテナは root で実行しない。Zabbix 公式コンテナの zabbix ユーザを使用する。
  - 全コンテナのネットワークは必要最小限に絞り、不要なポートを公開しない。
  - secrets/ および logs/ は .gitignore で除外する。
</security>
